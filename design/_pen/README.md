# Pencil(.pen) 디자인 관리 규칙 — 게임 디사이더

이 폴더는 **pen.dev(Pencil) 디자인 작업물**을 관리하는 영역입니다.
볼트의 공통 규칙(`Root's AI Brain/01 Projects/게이트웨이/04 화면설계/_pen/README.md`)을 이 리포에 맞춰 적용했습니다.

## 폴더 구조

```
design/_pen/
├── src/                    # .pen 소스 (Pencil MCP 전용) — git 커밋 대상
│   ├── game-decider.pen
│   └── images/             # 임포트한 이미지 — .pen 이 상대경로로 참조하므로 함께 커밋
├── exports/                # 파생물 — gitignore (재생성 가능)
│   ├── png/                # PNG (리뷰·문서 첨부)
│   └── html/               # HTML export (개발 전달용)
└── README.md
```

## ⚠️ Pencil MCP 는 `filePath` 인자를 무시한다

도구마다 `filePath` 를 받지만 실제로는 **Pen 앱에서 열려 있는 편집기**에 쓴다.
다른 경로를 지정해도 무시되므로:

1. 작업 전 `get_app_state` 로 *Currently active canvas editor* 가
   `design/_pen/src/game-decider.pen` 인지 확인한다.
2. 아니면 Pen 앱에서 **그 파일을 먼저 연다.**

실제 사고 사례(2026-08-13): 옮겨진 옛 경로(`game-decider/ui`)의 편집기가 열려 있어
작업이 전부 그쪽으로 들어갔고, **리포 루트에 `images/` 폴더가 생겼다**
(임포트 이미지가 `ui` 기준 상대경로로 저장됨). 나중에 수동으로 이동해야 했다.

> 임포트한 이미지는 `.pen` 과 **같은 폴더 기준 상대경로**로 참조된다.
> `.pen` 을 옮기면 `images/` 도 반드시 같이 옮길 것.

## 캔버스에서 고친 걸 코드에 반영하는 법 (2026-08-13 검증)

### 결론: **자동 머지는 안 되고, 변경분 추출은 정확히 된다.**

| 방법 | 결과 |
|---|---|
| `export_html` | ❌ 머지 불가. **인라인 스타일이 박힌 `div` 트리**로 나온다. 앱의 `.draw-card` 같은 클래스와 연결이 없고 1440×900 고정폭이라, 코드가 아니라 *시각 명세*다 |
| `export_nodes` | ❌ 이미지 래스터화(PNG/PDF)일 뿐 |
| **노드 트리 diff** | ✅ **이게 답이다.** `Get` 으로 스타일 속성을 읽어 이전 값과 비교하면 무엇이 얼마나 바뀌었는지 정확히 나온다 |

### 왕복이 성립하는 조건 — **노드 이름 = CSS 선택자**

임포트하면 노드 이름이 원본 태그(`div`·`span`·`article`)라 어느 CSS 규칙인지 알 수 없다.
그래서 정규화할 때 **이름을 선택자로 바꿔둔다**. 그러면 diff 결과가 곧 고칠 규칙이 된다.

```
.draw-card [pnf52] · width: 330 → 360      →  styles.css 의 .draw-card { width: }
.dc-pick   [FSRwd] · fill: (그라데이션) → #e0533d  →  .dc-pick { background: }
```

현재 '오늘의 도전' 프레임은 이 규칙으로 정리돼 있다:
`#dailyContent` · `.daily-head` · `.view-lead` · `.draw-deck` · `.draw-card` ·
`.dc-art` · `.dc-slot` · `.dc-body` · `.dc-tier` · `.dc-ach` · `.dc-desc` ·
`.dc-game` · `.dc-why` · `.dc-pick` · `.daily-foot`

### 작업 순서

1. Pen 에서 자유롭게 고친다 (크기·색·간격·정렬·타이포)
2. 저장(Ctrl+S)
3. Claudian 에게 "캔버스 변경분 반영해줘" → 트리를 읽어 현재 CSS 와 대조 후 `styles.css` 수정
4. 브라우저 스크린샷으로 확인

### 반영되는 것 / 안 되는 것

| | |
|---|---|
| ✅ | 크기·여백·간격, 색·그라데이션, 모서리·테두리, 폰트 크기/굵기, 정렬, 레이아웃 방향 |
| ⚠️ | 절대배치 ↔ 플렉스 전환 — 의도를 읽고 판단해야 함 |
| ❌ | **요소를 추가·삭제하는 변경** — HTML/JS 도 같이 고쳐야 하므로 "반영"이 아니라 새 구현 |
| ❌ | Pen 전용 효과(셰이더 등) — CSS 로 표현 못 함 |

> 임포트한 프레임은 **그 시점의 스냅샷**이다. 코드가 바뀌면 캔버스는 낡는다.
> 큰 변경 뒤에는 다시 임포트해서 기준선을 갱신할 것.

## 캔버스 ↔ 코드 동기화 규칙

### 왜 어긋났나

단일 원천이 없어서 양쪽이 각자 흘렀다. 구체적으로 세 가지가 겹쳤다.

1. **채팅에서 고친 건 캔버스로 안 돌아갔다.** 코드만 바뀌고 캔버스는 낡은 채로 남는데,
   다음 비교 때 그 낡은 캔버스가 기준이 되니 "왜 다르지"가 반복된다.
2. **캔버스에서 고친 걸 찾는 방법이 샘플링이었다.** 눈에 띄는 것만 골라 확인하니
   빠뜨린 게 나오고, 그래서 여러 번 되물어야 했다.
3. **캔버스 한 곳에 시안과 구현 스냅샷이 섞여 있었다.** 재임포트하면 손댄 게 날아가고,
   손대면 재임포트를 못 한다.

### 역할을 나눈다

| | 원천 | 사본 |
|---|---|---|
| **디자인 토큰** (색·모서리·타이포) | `.pen` 변수 | `tokens.json` → `styles.css :root` |
| **레이아웃·간격·구조** | 코드 | 캔버스의 '현재 구현' 프레임 |
| **새 시안** | 캔버스 | (구현되면 코드가 원천이 됨) |

토큰은 캔버스가, 레이아웃은 코드가 이긴다. 겹치는 영역을 없애는 게 핵심이다.

### 절차

**① 토큰 동기화** — 색·모서리·글자크기를 캔버스에서 바꿨을 때
```
"Pen 토큰 동기화해줘"
  → GetVariables() 로 .pen 변수 전량 추출
  → design/_pen/tokens.json 갱신
  → styles.css :root 갱신
  → node design/_pen/check-tokens.js 로 전수 대조
```
`check-tokens.js` 는 사람 눈이 아니라 **전수 비교**라 빠뜨리지 않는다.
실제로 이 체커를 처음 돌렸을 때 `--gold: var(--gold)` 같은 **순환 참조 5건**이
잡혔다 — 일괄 치환 스크립트가 `:root` 정의부까지 바꿔버린 것으로, 전설 배지 색이
죽어 있었는데 아무도 몰랐다.

**② 캔버스 변경 반영** — 레이아웃·구조를 캔버스에서 바꿨을 때
```
"캔버스 변경분 반영해줘"
  → 노드 트리를 읽어 이름이 선택자(.draw-card 등)인 노드의 스타일 수집
  → 현재 CSS 와 대조 → 어긋난 것만 수정
  → 브라우저에서 계산값으로 재확인 (스크린샷 아님)
```
전제: **노드 이름 = CSS 선택자**. 이름이 `div`/`span` 이면 어느 규칙인지 알 수 없다.

**③ 코드 변경 후 캔버스 갱신** — 채팅에서 UI 를 고쳤을 때 (그동안 빠져 있던 단계)
```
"바뀐 화면 캔버스에 갱신해줘"
  → 해당 화면만 재임포트 → '현재 구현' 영역의 옛 프레임 교체
```
이걸 해야 다음 비교의 기준이 최신이 된다. **이 단계를 건너뛴 게 반복 확인의 주범이었다.**

### 캡처 모드 — `?w=1920&h=1080`

Pen 내장 브라우저는 폭을 지정할 수 없고 매번 달라진다(실제로 한 세션 안에서
1222px → 2398px 로 바뀌어 앞뒤 프레임 폭이 어긋났다). 그래서 앱 쪽에 캡처용
쿼리 파라미터를 뒀다.

```
http://localhost:3000/?w=1920&h=1080#ach/collected
```

- `w` → `#app` / `#loginScreen` 폭 고정 + 가운데 정렬
- `h` → `--vh` 를 그 값으로 고정 (`100vh` 대신 이 변수를 쓴다).
  **최소 높이라서 내용이 길면 프레임이 늘어난다** — 잘리지 않게 하려는 것이다.
- `capture` 클래스가 붙어 LNB 가 sticky 대신 프레임 전체 높이로,
  애니메이션·트랜지션이 전부 꺼진다.

캔버스의 '현재 구현' 프레임은 **전부 1920 폭**으로 맞춘다. 폭이 섞이면 비교가 무의미하다.

### ⚠️ 애니메이션이 걸린 요소는 통째로 래스터화된다

`.view { animation: fade .25s ease }` 하나 때문에 `main` 이 편집 가능한 레이어가
아니라 **rectangle 한 장**으로 임포트됐다. 자식이 0개로 들어오면 이걸 의심할 것.
`.capture` 모드가 `animation: none !important` 로 막아준다.
(`animation-fill-mode: backwards` 로 콘텐츠가 안 보이던 것과 같은 계열의 함정이다.)

### 지켜야 할 것

- **`return-element` 는 잎 노드에.** 컨테이너에 걸면 응답이 50KB 를 넘어 잘린다.
  렌더 완료 확인 겸 값 검증은 `.gt-name` 같은 말단 요소로 한다.
- **임포트 전 브라우저 폭을 확인한다.** 위 캡처 모드를 쓰면 폭은 고정되지만,
  브라우저가 지정 폭보다 좁으면 여전히 다른 breakpoint 가 들어온다.
- **검증은 계산값으로.** Pen 의 요소 스크린샷은 가로로 잘리거나 반복되는 일이 잦아
  개수·크기 판단에 못 쓴다. `return-element` 의 computed style 을 본다.
- **캔버스 편집 뒤에는 Ctrl+S.** Pen 은 자동 저장이 들쭉날쭉하고, 한 번은 빈 문서를
  덮어써 작업이 날아간 적이 있다(git 에서 복구).

## 규칙

1. **`.pen` 은 `src/` 에만** 둔다. **Pencil MCP 도구로만** 접근하고, Read/Grep으로 열지 않는다.
2. **파일 단위 = 모듈/기능별 1파일.** 한 파일 안에서 화면을 프레임(Frame)으로 나눈다.
3. `exports/` 는 언제든 재생성 가능한 **파생물**이다. 원본은 항상 `src/*.pen`.
4. git: `src/*.pen` 은 커밋, `exports/` 는 무시 (`.gitignore` 참조).

## 명명 규칙

| 대상 | 규칙 | 예시 |
|------|------|------|
| .pen 파일 | `<기능/모듈>.pen` | `game-decider.pen` |
| PNG export | `<pen파일명>-<프레임>.png` | `game-decider-스핀화면.png` |
| HTML export | `<pen파일명>-<프레임>.html` | `game-decider-스핀화면.html` |

## 작업 흐름

1. `get_app_state({include_schema:true, include_canvas_design:true, include_scripts_and_shaders:false})` 로 스키마 파악 (**모든 작업의 전제**)
2. `execute` 로 프레임·레이어 생성/수정
3. `get_screenshot` 으로 검토
4. 필요 시 `export_nodes`(PNG) / `export_html`(HTML) 로 `exports/` 에 내보내기
